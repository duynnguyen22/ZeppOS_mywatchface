# Amazfit Active 2 (Round) Watch Face Foundation — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up a Zepp OS watch face project targeting the Amazfit Active 2 (Round) that builds, previews in the simulator, installs on the physical watch, and has a unit-tested pure-logic core ready for a real design.

**Architecture:** Pure geometry and formatting logic live in dependency-free modules that run under plain Node and are unit tested; the watch face entry file is a thin shell that feeds those values into the Zepp widget API. This split is what makes the project testable at all, since Zepp widget code runs only on-device.

**Tech Stack:** Zepp OS 5.0 (API level 4.2), `@zeppos/zeus-cli`, Zepp OS Simulator, Node.js 22 with built-in `node:test`. No runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-09-12-watchface-foundation-design.md`

## Global Constraints

- Target device is **Amazfit Active 2 (Round) only**: 466 × 466, round, Zepp OS 5.0, API level 4.2.
- `designWidth` is **466**.
- Valid `deviceSource` values: `8913152`, `8913153`, `8913155`, `8913159`, `10092800`, `10092801`, `10092803`, `10092807`. `8913152` and `10092800` are the primary entries.
- Do **not** add Active 2 Square (390 × 450, `deviceSource` `10223872`/`10223873`/`10223875`) as a target.
- Node.js `>= 14.0.0` is required by Zeus CLI. Installed version is v22.19.0.
- `watchface/layout.js` and `watchface/format.js` MUST NOT import any Zepp API (`hmUI`, `@zos/*`). They must run under bare Node. This is what keeps them testable.
- No test framework is installed. Tests use Node's built-in `node:test` and `node:assert`.
- The API style (global `hmUI` vs `@zos/*` imports) is determined by inspecting the generated template in Task 2, never assumed.

// Pure geometry for the Amazfit Active 2 (Round), 466x466.
// MUST NOT import any Zepp API - this module runs under bare Node so it
// can be unit tested.

const SCREEN = { width: 466, height: 466 }
const CENTER = { x: SCREEN.width / 2, y: SCREEN.height / 2 }
const RADIUS = SCREEN.width / 2

// Angle in degrees clockwise from 12 o'clock.
function polar(angleDeg, distance) {
  const radians = ((angleDeg - 90) * Math.PI) / 180
  return {
    x: CENTER.x + distance * Math.cos(radians),
    y: CENTER.y + distance * Math.sin(radians),
  }
}

// True when all four corners of the rect sit inside the circular face,
// inset by `margin`. Catches content the round bezel would clip.
function fitsOnFace(rect, margin = 0) {
  const limit = RADIUS - margin
  const corners = [
    [rect.x, rect.y],
    [rect.x + rect.w, rect.y],
    [rect.x, rect.y + rect.h],
    [rect.x + rect.w, rect.y + rect.h],
  ]
  return corners.every(
    ([x, y]) => Math.hypot(x - CENTER.x, y - CENTER.y) <= limit
  )
}

module.exports = { SCREEN, CENTER, RADIUS, polar, fitsOnFace }
```

// Pure display formatting.
// MUST NOT import any Zepp API - this module runs under bare Node so it
// can be unit tested.

function pad2(n) {
  return String(n).padStart(2, '0')
}

function formatTime(hour, minute, use24h = true) {
  if (use24h) {
    return `${pad2(hour)}:${pad2(minute)}`
  }
  const twelve = hour % 12 === 0 ? 12 : hour % 12
  return `${twelve}:${pad2(minute)}`
}

function formatSteps(steps) {
  return String(steps).replace(/\B(?=(\d{3})+(?!\d))/g, ',')
}

function formatBattery(percent) {
  const clamped = Math.max(0, Math.min(100, percent))
  return `${clamped}%`
}

module.exports = { pad2, formatTime, formatSteps, formatBattery }
```

## What this plan does NOT cover

The visual design of the actual watch face. That work is blocked on the
reference image and gets its own spec and plan.

Two decisions should be settled before that second plan is written:

1. **Always-on display (AOD).** Zepp OS treats AOD as a separate
   stripped-down layout authored alongside the main one. Designing it in
   from the start is substantially easier than retrofitting it.
2. **Editable regions.** Whether the user should be able to customise
   complications or background from the Zepp app, which changes the widget
   structure significantly.
